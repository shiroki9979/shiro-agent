# Markdown 檢查修復

> 建立日期：2026-10-05
> 最後更新：2026-10-05

## 執行流程

1. 確認目標專案、要求修復的檔案或目錄，以及現有工作區變更。
   讀取 [check-links](../check-links/SKILL.md) 與
   [check-markdownlint](../check-markdownlint/SKILL.md)，依其流程選擇入口與設定。
   保留既有變更；修正限於要求範圍內的文件問題。
2. 執行要求的檢查，取得目前失敗的檔案、行號、URL、規則代碼與退出碼。
   既有錯誤輸出可作為定位線索，實際修復以前以目前檔案重現。
   將問題分成文件錯誤、設定／工具錯誤、網路／權限限制，優先修復可確定的
   文件錯誤。工具無法執行時，記錄阻礙及仍可完成的修正。
3. 依下列兩種修復方式做最小變更，保留內容語意、程式碼範例與文件結構。
   有實質修改且文件已含最後更新日期時，依既有格式更新日期。
4. 檢視差異，確認修正沒有誤改正文、連結目的、範例或使用者既有變更。
5. 使用原先的版本、設定與範圍重新執行檢查。受影響的文件在要求範圍內，
   同時重跑連結與格式檢查，避免格式修正引入死連結，或連結修正違反格式規則。
   單檔快速驗證後，仍完成原要求範圍的驗證。
6. 剩餘可確定的文件錯誤繼續修復；若同一失敗重現且沒有新的修正依據，
   列為未解決並停止該項重試。空掃描、登入限制或網路阻礙均列為未驗證，
   以實際驗證結果判定完成狀態。

## 連結修復

- **相對路徑**：從連結所在文件目錄解析目標，查找實際檔案、搬移紀錄或
  明確替代文件，再校正路徑與大小寫。保留原本的查詢參數與錨點語意。
- **標題錨點**：比對目標標題與渲染平台的 anchor 規則；標題修改時檢查
  要求範圍內的引用。工具通過不足以證明錨點正確。
- **外部 URL**：確認原來源的轉址、官方新位置或識別碼後替換。
  找不到可靠替代來源時，列出原 URL、失敗原因與待確認選項。
- **暫時性失敗**：DNS、TLS、逾時、429 或登入限制先診斷原因。
  有依據時針對失敗連結有限重試；保留無法驗證的連結與未解決狀態。
  禁止以刪除連結、加入 ignorePatterns 或放寬成功狀態碼掩蓋失敗。

## Markdown 格式修復

先使用專案既有的 Markdown 修復入口；缺少入口時，從格式檢查技能所選的
命令沿用版本與設定，加入 `--fix`，並限制為要求範圍內的受影響檔案。
例如在沿用後備版本且專案已有設定時：

```bash
npx --yes markdownlint-cli2@0.23.3 --fix --no-globs ":docs/usage guide.md"
```

將範例替換為實際路徑；需要基礎設定時，沿用格式檢查技能的 `--config`。
`--no-globs` 防止設定中的 globs 讓自動修復擴大到其他文件。
若設定覆寫 `fix: false`，保留設定並改用手動修復。

自動修復後逐項處理剩餘規則，例如標題階層、表格空行與行長。
換行時保留 Markdown 語意，保持 URL、行內程式碼與程式碼區塊內容完整。
禁止以停用規則、新增 lint-disable 或擴大忽略範圍取代修正；規則政策變更
須有使用者明確要求。

## 完成條件與回報

要求範圍內可確定的文件錯誤已修復，並有修復後的檢查結果。
只有實際掃描到文件且兩項檢查通過的範圍可標示「修復並驗證通過」。
其餘情況回報「部分修復」或「驗證受阻」，附上未解決項目與原因。

精簡列出修改檔案與修正內容、兩項檢查的命令／範圍／退出碼，以及仍需確認
的替代來源或未驗證項目。
