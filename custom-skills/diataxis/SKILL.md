# Diátaxis 文件撰寫框架

本技能用於指導技術文件的分類、規劃、撰寫與審查，嚴格遵守 [Diátaxis](https://diataxis.fr/) 四大象限架構，杜絕跨象限的「內容污染（Quadrant Pollution）」。

---

## 核心工作流程（Protocol）

當接收到文件撰寫或審查需求時，**下筆前必須先鎖定象限**並輸出以下宣告區塊：

```markdown
### Diátaxis 象限鎖定
- **目標象限**：[Tutorial | How-To | Reference | Explanation]
- **目標讀者**：[初學者 | 具備基礎的操作者 | 查詢規格者 | 理解架構背景者]
- **核心目標**：[用一句話說明此文件欲達成的單一目的]
- **排除內容（Avoid）**：[本文件嚴格禁止放入的混雜內容]
```

與使用者確認或自我對齊後，嚴格依照該象限的規範撰寫。

## 四大象限詳細規範

```text
               實作導向 (Practical)
                     ▲
                     │
      Tutorial       │      How-To Guide
  (學習導向 / 循序引導)  │  (問題導向 / 解決任務)
                     │
 ────────────────────┼────────────────────► 獲取知識 (Theoretical)
                     │
     Reference       │      Explanation
  (資訊導向 / 客觀規格)  │  (理解導向 / 架構脈絡)
                     │
                     ▼
```

### 1. Tutorial（學習導向 / 入門教學）

- **定位**：帶領初學者完成首次端到端的成功體驗（Learning by doing）。
- **原則**：
  - 給予確定性、每一步皆能成功且具備即時回饋的連續指令。
  - 依序提供最少必要動作。
- **絕對禁忌（Avoid）**：
  - 禁止解釋底層架構原理或為什麼這樣設計（留給 Explanation）。
  - 禁止提供多種替代方案或分支選項（只給一條黃金路徑）。
  - 禁止展開完整的 API 參數表或配置清單（留給 Reference）。

### 2. How-To Guide（問題導向 / 操作手冊）

- **定位**：指引已具備基礎知識的使用者解決特定現實問題（Problem-solving）。
- **原則**：
  - 針對具體情境或特定錯誤提供步驟指南。
  - 假設讀者已具備基本概念，直接切入核心任務。
- **絕對禁忌（Avoid）**：
  - 禁止從零基礎概念教起（留給 Tutorial）。
  - 禁止放入長篇架構辯論或歷史背景（留給 Explanation）。
  - 禁止僅列出規格而不給實際操作步驟（留給 Reference）。

### 3. Reference（資訊導向 / 規格手冊）

- **定位**：準確、嚴謹、客觀地描述機器、API、配置或指令的真實狀態（Information）。
- **原則**：
  - 提供全面、客觀且一致的結構化資訊（參數型別、預設值、回傳格式）。
  - 保持純粹的描述性與中立性。
- **絕對禁忌（Avoid）**：
  - 禁止放入 Step-by-step 教學或實作流程（留給 How-to）。
  - 禁止表達個人主觀推論或架構思維（留給 Explanation）。
  - 禁止假設讀者情境並給出教學步驟（留給 Tutorial）。

### 4. Explanation（理解導向 / 架構闡述）

- **定位**：提供宏觀視野，解釋背景脈絡、設計哲學與架構取捨（Understanding & Why）。
- **原則**：
  - 闡明「為什麼這樣設計（Why）」、「各選項取捨（Trade-offs）」與「系統概念間的關係」。
  - 允許更廣泛的討論、歷史成因與未來方向。
- **絕對禁忌（Avoid）**：
  - 禁止提供操作步驟或程式安裝流程（留給 Tutorial / How-to）。
  - 禁止充當參數查詢手冊或 API 字典（留給 Reference）。

## 象限純度檢核表（Purity Checklist）

在完成任何技術文件產出時，使用以下檢核表進行驗證：

| 檢核項目 | 合格標準 |
| :--- | :--- |
| **單一目的性** | 全篇僅滿足單一象限需求，無跨象限段落 |
| **語氣一致性** | Tutorial 循序引導；How-to 乾脆俐落；Reference 客觀中立；Explanation 深入論證 |
| **交叉連結** | 當需要額外資訊時，使用超連結導向其他象限文件，而非原地展開 |
